# Project Structure

## Overview

Laravel 8 monolith — Blade templates serve the initial HTML, Vue.js handles all UI interaction, and a versioned REST API (`/api/v1/`) handles data.

```
app/
  Http/
    Controllers/        # Web + API controllers
      Auth/             # Laravel auth scaffold (mostly unused — JWT used instead)
      BaseController.php    # Shared CRUD logic (index, store, update, destroy, paginate, filter)
      Controller.php        # Base JSON response helpers
      AuthController.php    # JWT login/logout/me
      [Resource]Controller.php  # One controller per domain entity
    Middleware/         # JWT auth, admin role check, locale cookie
  Models/               # Eloquent models
    BaseModel.php       # Shared model base
    [Entity].php        # One model per table
  Traits/               # Reusable PHP logic
    PasswordValidationTrait.php
    FieldNameValidator.php
    CurrencyHandler.php
  Providers/
    SystemSettingsServiceProvider.php  # Loads system_settings into config at boot
  Events/
    EventCreated.php    # Broadcast event for real-time feed

config/                 # Laravel config files; jwt.php and websockets.php are key
database/
  migrations/           # One file per schema change, named with timestamp
  seeders/              # ClassificationsSeeder, LanguagesSeeder, DatabaseSeeder
  factories/

routes/
  api.php               # All API routes under /api/v1/, JWT-protected
  web.php               # Blade view routes, session-auth protected

resources/
  js/
    app.js              # Vue app entry point — registers all components globally
    bootstrap.js        # Axios config, JWT interceptors, Laravel Echo/Pusher setup
    components/         # Vue SFCs (.vue files), one per UI section/feature
    utils/
      functions.js      # Shared Axios wrappers (axiosGet, axiosPost, axiosPatch, axiosDelete)
                        # Also exports modal helpers and loadTranslations()
  views/                # Blade templates — mostly thin shells that mount a Vue component
    layouts/            # App layout (nav, sidebar)
    auth/               # Login, password update views
  lang/
    pt_BR/              # Primary language files
    en/ es/ fr/         # Additional locales
  sass/
    app.scss            # Main stylesheet (imports Bootstrap)

public/
  js/                   # Compiled JS output (git-ignored, generated by Mix)
  css/                  # Compiled CSS output

tests/
  Unit/                 # PHPUnit unit tests
  Feature/              # PHPUnit feature/integration tests
```

## Key Conventions

### Backend

- All resource controllers extend `BaseController`, which provides standard `index`, `store`, `update`, `destroy`, `paginate`, and `filter` methods.
- Validation rules live in the Model (`rules()` and `feedback()` methods), not in controllers.
- All API responses are JSON. Use the response helpers on `Controller`: `response()`, `responseGeneric()`, `responseDataNotFound()`, `responseError()`.
- API routes are grouped under `/api/v1/` with `jwt.auth` middleware. Admin-only routes additionally use the `admin` middleware.
- Models use explicit foreign key names (e.g., `profiles_id`, `classifications_id`, `types_id`).
- Table names are `snake_case`; model class names are `PascalCase`. Some models deviate (e.g., `ids_agent`, `system_setting` — lowercase class names).

### Frontend

- All Vue components are registered globally in `app.js` using kebab-case names (e.g., `events-component`).
- API calls go through the helpers in `utils/functions.js` — do not use `axios` directly in components.
- `API_URL` is exported from `utils/functions.js`; use it as the base for all API calls.
- JWT token is stored in a cookie (`token=...`) and injected into Axios headers via an interceptor in `bootstrap.js`.
- Bootstrap modals are controlled via jQuery (`showModal`, `closeModal` from `utils/functions.js`).
- Translations are loaded at runtime via `loadTranslations(obj, domain, attr)`.

### Routing

- Web routes use Portuguese slugs (`/eventos`, `/usuarios`, `/classificacoes-de-risco`).
- API routes use English resource names (`/api/v1/event`, `/api/v1/user`).
- The event store route has a custom throttle (`throttle:store-events`) separate from the default API throttle.
